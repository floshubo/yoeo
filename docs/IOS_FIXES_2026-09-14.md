# iPhone fixes — September 14, 2026

## Changes

- Disable automatic native content insets because the app already handles safe areas in CSS. Size the native app to the full WebView and use a white iOS background to avoid exposed green below navigation.
- Treat Capacitor as an installed app. Hide the automatic install sheet, profile install button, and installation instructions in settings. Browser installation remains available.
- Default the backend allowlist to `capacitor://localhost` when `NATIVE_APP_ORIGINS` is absent. Explicit configuration still overrides this default.
- Use the existing hosted API at `https://yoeo.onrender.com` for native bundles when `VITE_API_BASE_URL` is absent. Web requests remain relative. Release preparation still validates the explicit production configuration.
- Include the account session in analysis requests and replace generic network errors with connection guidance.

## Evidence and checks

The production health endpoint returned HTTP 200 with the AI provider configured, but no `Access-Control-Allow-Origin` header for `Origin: capacitor://localhost`. This prevents the native WebView from reading the API response. No user photos were submitted during diagnosis.

All 40 automated tests in the release commit passed in an isolated snapshot, including native preflight and analysis-response coverage. TypeScript and the production Vite build passed. Capacitor iOS sync completed in the working project. Browser tests with a simulated native platform verified installation visibility, API routing, and navigation reaching the viewport bottom; the web installation flow also passed.

## Release steps

1. Deploy the backend changes. On Render, set `NATIVE_APP_ORIGINS=capacitor://localhost,http://localhost` (preserving any other required origins), especially if this variable is currently present but empty. Check an OPTIONS request to `/api/analyze` from `capacitor://localhost` returns 204 and a matching `Access-Control-Allow-Origin` header.
2. Create a new signed iOS build using the existing Mac release instructions and production environment. Install it on the affected iPhone.
3. Check Home, Profile, scanner review, and sheets in portrait and landscape: navigation labels should be visible, the home indicator should have appropriate padding, and no green strip should cover the bottom. Check that install prompts never appear in the native app.
4. Analyze photos as a guest and as a signed-in user; verify results load and the correct account allowance is used.

The backend has not been deployed by this change, and a signed IPA has not been created. Actual iOS safe-area behavior and live photo analysis still require device verification; this Windows environment cannot run Xcode or the iOS simulator.
